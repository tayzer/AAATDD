# Native loader observation

The development tool now combines initial/final module snapshots with Windows per-process DLL load notifications. A notification retains the full filename even if the DLL unloads before the managed observer polls. The runtime verifier requires registration identity, continuous event numbers and a matching final count. Missing events, unsupported paths, unavailable files, queue overflow or failed registration prevent PASS.

Microsoft documents that [loader callbacks cannot safely call another module](https://learn.microsoft.com/en-us/windows/win32/devnotes/ldrdllnotification). TADA therefore uses a small native callback that copies into a preallocated queue with inline lock-free atomics. Managed code, allocation, hashing and file I/O happen after the callback returns. Initial snapshots account for modules already present when observation starts. The [registration API](https://learn.microsoft.com/en-us/windows/win32/devnotes/ldrregisterdllnotification) can change or disappear; unsupported registration fails closed rather than silently falling back to snapshot-only coverage.

The queue holds 4,096 notifications, each with up to 2,047 UTF-16 path characters. Capacity/path errors are explicit evidence gaps. Callbacks retain paths, not immutable copies of mapped executable pages. Byte identities are observed from files and checked against captured artifacts/platform inputs; the existing local advisory trust and stable-file assumptions still apply. Native observation ends at the agreed final checkpoint or graceful exit. This is not protection against an actor controlling the process, OS or evidence.

Source builds use build-only Zig 0.15.2 from its [official release archive](https://ziglang.org/download/0.15.2/zig-x86_64-windows-0.15.2.zip), pinned to SHA-256 `3a0ed1e8799a2f8ce2a6e6290a9ff22e6906f8227865911fb7ddedc3cc14cb0c`. The bootstrap verifies the archive and stores it below `.artifacts/`; no compiler is installed system-wide. The packaged tool includes TADA's own native DLL, not Zig or its compiler libraries. Source compilation links no CRT; the native test inspects PE imports and requires only `KERNEL32.dll`. Installed-package users need no C compiler.

Controls load and immediately unload an owned native fixture, prove it is absent from the process module list before polling, and require the queued event to remain. Separate end-to-end controls reject an unselected transient DLL and accept a captured/reviewed copy under the same business expectations. Arbitrary custom build-task file reads remain a separate open provenance boundary.
