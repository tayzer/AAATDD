# TADA 0.1.0-alpha.12

First public alpha candidate, prepared on 2026-11-09. Publication is subject to the [remaining release gates](../validation/release-candidate-12.md).

## Supported workflow

TADA combines a host-controlled agent plugin with a repository-local .NET tool. Human-approved Gherkin, assertions and fixture support form immutable exact-byte baselines. The verifier runs a separate application through Reqnroll/MSTest/MTP and checks retained native evidence. Results distinguish PASS, FAIL and INDETERMINATE. Baseline amendments and earlier trustworthy failures retain their history.

The plugin handles ordinary feature, defect, refactor and chore requests. Business expectations require human agreement and approval. Native `dotnet test` and Visual Studio Test Explorer Run/Debug are supported alongside recorded TADA execution. The run and verify commands show elapsed phases and ten-second updates. JSON mode keeps structured stdout free of progress messages.

The plugin ZIP includes its matching verifier feed, installation README and local marketplace catalog. Extract it and register the extracted root using the documented Codex CLI commands. No TADA source build is needed for this installation route.

This candidate fixes checkpoint sharing races exposed by merged-main Windows CI and local end-to-end validation. The observer defers reading an in-progress request until the legacy helper releases its write handle. The generated helper retries transient acknowledgement-read sharing conflicts within its ten-second deadline. Matching run identities and required final snapshots remain enforced. Existing projects need review and approval when adopting the revised captured helper.

## Requirements and limits

- Windows x64, .NET SDK 10.0.403 and Git for Windows. Building TADA from source also needs PowerShell 7 and downloads a checksum-pinned Zig compiler into the workspace.
- Supported acceptance stack is Reqnroll 3.3.4, MSTest 4.5.2, MTP 2.5.2 and native Messages protocol 30.1.0.
- Local advisory L1 trusts the host, verifier, approved fixtures, installed SDK, pinned package tools and reviewed custom-task declarations. Read the [provenance policy](../validation/provenance-audit.md) before interpreting PASS.
- Scenario Outlines, partial obligation removal, other platforms/runners and protected independent assurance remain unsupported.
- Arbitrary I/O, network data, non-.NET child tools and manual image mapping are outside automatic observation. Inputs must remain stable during execution. Workspace paths containing commas or semicolons are unsupported.

## Install

The proposed GitHub prerelease assets are `Tada.Cli.0.1.0-alpha.12.nupkg`, `TADA-0.1.0-alpha.12-win-x64.zip`, `TADA-plugin-0.1.0-alpha.12.zip` and `SHA256SUMS`. Compare downloaded hashes with the published checksum file before installation.

Extract the install bundle and follow its README for the local-feed CLI installation. Follow [plugin setup](../plugin.md) for automatic workflow selection, and [quickstart](../quickstart.md) for baseline review, execution, retained verification and recovery. The matching plugin includes its own verifier feed. NuGet.org availability is not assumed.

Early testers may have a different development build cached under the same unpublished alpha.12 version. Use an isolated package cache and CLI home for candidate validation. Compare package hashes with the release manifest before migrating a project, review changed captured tool or fixture bytes, and retain old approvals and runs.

The requester accepted ordinary installation and API development. The actual TODO project retains human-approved migrations and a 14-case recorded PASS, also verified by this candidate. Focused regression and end-to-end controls, exact candidate source identity and downloadable artifact hashes are tracked in [candidate validation](../validation/release-candidate-12.md).

Changed oracle bytes need a new comparative review and human approval. A retry retains earlier history. Keep the extracted feed available for later local-tool restore.
